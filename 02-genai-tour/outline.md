## 1. 學員假設與學習目標

- **學員**：會用 Colab（ML pp.5–6）、softmax 與蒸餾溫度（DL pp.69–71）、`requests`／JSON／`.env`（Vibe 11–12）、system 與 user 提示（Vibe 01–02）。**沒有**呼叫過 LLM SDK（curriculum-analysis K6）。
- **不教**：訓練、微調。

學完後，學員能夠：

1. **執行**文字生成 `pipeline` 與 fp16 的 `DiffusionPipeline`。
2. **呼叫**一次雲端 LLM（Gemini 免費方案），金鑰放在 Colab 密鑰或 `.env`，不寫在程式裡（沒有金鑰時用開放模型備案）。
3. **說明**輸出為什麼每次不同（抽樣），溫度怎麼改變機率分布。
4. **重現**輸出（seed）並從模型卡讀出授權。

## 2. 概念地圖

| 概念 | 白話定義 | 解決的問題 | 先備 | 例子 | 常見誤解 |
|---|---|---|---|---|---|
| pipeline | 把前處理、模型、後處理包成一個呼叫 | 三行跑起模型 | Vibe 11 套件 | 文案 | pipeline 就是一個模型 |
| Hugging Face Hub | 放模型權重與模型卡的網站，名字＝組織／模型 | 模型從哪來、能不能商用 | — | `Qwen/Qwen2.5-0.5B-Instruct` | 要帳號才能下載 |
| 自己跑 vs API | 模型在自己的 GPU vs 在廠商伺服器 | 資料去哪、要不要金鑰 | D1-1 開放權重 vs API | Part A vs Part C | API 也是在自己電腦跑 |
| 下一個 token 的機率 | 模型對每個可能 token 的機率 | 為何會不同 | DL softmax | 「特色是＿」 | 模型直接給一個答案 |
| logit → softmax | 模型輸出分數，softmax 變成加總為 1 的機率 | 溫度插在哪裡 | DL softmax | z＝[2,1,0] → [0.67,0.24,0.09] | logits 就是機率 |
| 抽樣 | 照機率抽一個 | 多樣性 | D1-1 p_θ | do_sample | 不同＝壞掉 |
| 溫度 | softmax(z/T) | 控制穩定 vs 多樣 | DL pp.69–71 | T=0.2/1/1.5 | 溫度越高品質越好 |
| seed | 固定亂數起點 | 可重現 | — | Generator(42) | 換 GPU 也一定一樣 |
| 模型卡授權 | 模型卡的 license 欄位 | 能不能商用 | — | Apache-2.0、OpenRAIL-M | 能下載就能商用 |

## 5. 常見誤解

- 每次不同＝模型壞掉（「生成＝依機率抽籤」）。
- logits 就是機率（「模型吐出的是分數（logit）」）。
- 固定 seed 到處都一樣（「seed（亂數種子）」）。
- 能下載就能商用（Lab 4／4、隨堂檢核第 4 題）。
- VS Code 連 Colab 也能用 Colab 密鑰（「把金鑰交給程式：兩種放法」）。
