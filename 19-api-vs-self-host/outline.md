# D5-3 · 雲端 API 還是自架模型

> 依據：`planning/slide-plan/D5-support-desk.md` 的 D5-3。**狀態：講師指示自動核准（2026-11-26，day5-done）**。
> 時間：2 小時。**不教**（Agent 模組）：串流、schema 強制輸出、tool calling、MCP；只認名字：Ollama／GGUF（○）、NF4／GPTQ／AWQ（△）。

## 1. 學員假設與學習目標

- **學員**：Vibe 11–12 用過 `requests`、JSON、`.env`；D1-2 呼叫過一次 API；D1-4 學過 VRAM 估算；D5-1 token 成本；D5-2 generate、溫度、KV cache；D2-4 VQ。

學完後，學員能夠：

1. **讀懂** SDK 呼叫與 usage。
2. **算出**每 1,000 張的成本（雲端、自架）。
3. **要求** JSON 並用 `json.loads` 驗證、重試。
4. **自架**同一任務（chat template、generate、4-bit）。
5. **填寫**開放 vs 封閉決策表。

## 2. 概念地圖

| 概念 | 白話定義 | 解決的問題 | 先備 | 例子 | 常見誤解 |
|---|---|---|---|---|---|
| 決策表 | 五欄＋證據 | 採購決定 | D1-1 | 成本、個資、授權、延遲、品質 | 只比準確率 |
| usage | API 回報的 token 數 | 成本 | D5-1 | 輸入 300、輸出 60 | 用字數估 |
| JSON 驗證 | 解析＋檢查欄位與值＋重試 | 模型格式不穩 | Vibe JSON | 單引號、「退貨」 | 提示詞說了就會照做 |
| chat template | 對話包成訓練時的格式 | 自架要對齊 | D5-2 | im_start | — |
| 量化 | 權重用更少位元 | VRAM | D1-4、D2-4 | 7B：14 → 3.5 GB | 4-bit 一定很差 |

## 5. 常見誤解

- 提示詞說只輸出 JSON，模型就一定照做（第 7、8 頁）。
- 4-bit 一定比較差、或一定一樣好：要量（第 21 頁）。
- 開放模型什麼都能做（第 25 頁：授權依大小不同）。
